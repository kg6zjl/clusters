What we're proud of, and what isn't finished

Asked directly, so answered directly. This is a running system, not a demo, and the interesting part is which parts held under pressure — and which ones are still obviously not good enough.

What held up

  • The agent has never needed a write credential. Everything it has fixed reached the cluster as a reviewed pull request. That is the whole design, and it is the thing that kept working on the days when the fastest path would have been to poke the cluster directly.
  • Read-only RBAC turned out not to be limiting. With broad get, list, watch the agent could diagnose almost everything on its own — including the failures that normally need a shell. The gap was never "not enough permission to write"; it was missing reads, and each one was added with a comment saying which diagnosis it unblocked. That is a much better problem to have.
  • The agent cannot read a secret. Not one, anywhere. A public repository plus an agent that reads logs for a living is normally a bad combination; this is the property that makes it survivable, and it means the agent cannot leak what it cannot see.
  • Half-broken paging kept paging. When one notification leg was dead for hours, the other one kept delivering, and the failure was reported with the name of the broken leg rather than as a mystery. That is soft failure earned by doing the boring thing — sibling routes — before it was needed.
  • The fix for a broken notification path was surgical. The tempting move was to disable the kill switch on the tunnel. Instead the exemptions were scoped to the notification destinations, so the rest of the cluster kept the privacy property it was built for. Saying no to the quick global fix is the kind of thing this setup is supposed to make normal.
  • Stateful workloads moved onto replicated storage with no data loss, using a two-stage pattern that only destroys the fallback after the new storage has been wrong-proof for a while. Unglamorous, irreversible-if-done-carelessly work, done carefully.
  • This site exists because the agent wrote its own runbooks. Every lesson on it was recorded where it was learned — a skill, a comment, a runbook — and then read back by the agent on a later task. The routing knowledge on the Network page went from an incident, to a skill, to a published page without a human transcribing anything.
  • The failure modes got written down instead of hidden. Approval fatigue, the self-recovery trap, the runner RBAC hole, the whitelist that hides the answer: naming those is the difference between a design and a brochure.

What isn't finished

  • The runners are still cluster-admin with blanket egress. The one component that holds the widest credentials is the one that has not been given the treatment everything else got. It is on the list, and it is the honest headline weakness of this setup.
  • Approval fatigue is real. An approval gate stops mattering when it fires twenty times a day. The countermeasure is fewer, better-scoped gates and more changes taking the repository path — but it is a moving target, not a solved problem.
  • Some knowledge still lives only inside the running pod. Skills are versioned in git, but a copy on a pod's volume can drift from the repository and quietly outlive the file that replaced it. Versioning the knowledge is half the job; making sure the pod reads the versioned copy is the other half.
  • The agent is one mishap away from being unable to work, and the recovery is a human. That is an accepted trade — no self-modification without approval — but it means the human is a single point of failure, and the design should say so out loud.
  • No page here should be trusted over the repository. Documentation drifts; the manifests and the runbooks are the truth, and a site like this is a summary of what they said when it was written.

The takeaway, if you build one thing

Give the agent read access to everything and write access to nothing, then make the pull request the only way it can change the world. It is a small amount of design work, it holds up under pressure, and it is the reason an agent with real operational reach is safe to leave running in a home cluster overnight.
